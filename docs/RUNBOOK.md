# دليل التشغيل، النسخ الاحتياطي، والاستجابة للحوادث (Operations Runbook)

## 1. أوامر التشغيل الأساسية

| المهمة | الأمر | الوصف |
| :--- | :--- | :--- |
| تشغيل التطوير والمعاينة | `npm run dev` | يشغّل الخادم والواجهة على المنفذ `3000`. |
| فحص الأنواع (Typecheck) | `npm run lint` | يتحقق من سلامة كود TypeScript (`tsc --noEmit`). |
| تشغيل اختبارات الوحدات | `npm test` | يشغّل اختبارات خط الأنابيب وفحوص الأمان وSEO. |
| تشغيل مجموعة التقييم (32 حالة) | `npm run eval` | يتحقق من نجاح جميع حالات التقييم الـ 32 بنسبة 100%. |
| بناء نسخة الإنتاج | `npm run build` | يبني حزم الواجهة وتطبيق PWA. |
| تشغيل بيئة Docker الكاملة | `make docker-up` | يشغّل `web`, `worker`, `postgres (pgvector)`, و`caddy`. |

## 2. استخدام مفتاح الإيقاف الفوري (Global Kill Switch)

في حال رصد أي خلل في مصدر خارجي أو رغبة رئيس التحرير في إيقاف الأتمتة فورًا:
1. **من لوحة التحكم**: افتح `/admin` واضغط زر **«تفعيل مفتاح الإيقاف الفوري (Kill Switch)»** في الشريط العلوي.
2. **عبر واجهة البرمجة**:
   ```bash
   curl -X POST http://localhost:3000/api/newsroom/kill-switch \
     -H "Content-Type: application/json" \
     -d '{"active": true}'
   ```
3. **عبر متغيرات البيئة**: اضبط `KILL_SWITCH_ACTIVE="true"` في `.env` وأعد تشغيل العامل.
- **الأثر الفوري**: تتوقف جميع مهام النشر الآلي خلال أقل من دقيقة وتتحول جميع المخرجات إلى `needs_review`.

## 3. النسخ الاحتياطي المشفر والاسترجاع (Backup & Restore)

### أ) إنشاء نسخة احتياطية مشفرة يوميًا:
```bash
BACKUP_ENCRYPTION_KEY="your-strong-passphrase" bash scripts/backup-db.sh
```
ينشئ السكربت ملف تفريغ مضغوط ومشفر بـ AES-256 (`backups/almizan_YYYYMMDDTHHMMSSZ.sql.gz.gpg`) ويحذف النسخ الأقدم من 30 يومًا.

### ب) اختبار استرجاع النسخة الاحتياطية (Restore Procedure):
```bash
gpg --decrypt --passphrase "$BACKUP_ENCRYPTION_KEY" backups/almizan_TIMESTAMP.sql.gz.gpg \
  | gunzip \
  | psql "$DATABASE_URL"
```

## 4. الاستجابة للحوادث التحريرية (Incident Response)

- **حادثة 1: صدور تصويب من المصدر الرسمي بعد نشر المقال**:
  1. ادخل إلى `/admin` -> طابور المراجعة والمحرر -> اختر المقال المنشور.
  2. عدّل المتن واحفظ نسخة جديدة (تُحفظ تلقائيًا في `article_versions` مع سبب التعديل).
  3. أضف نص التصحيح في حقل **«إصدار تصحيح علني أسفل المقال»** واضغط نشر؛ سيظهر الصندوق علنًا أسفل المقال وفي صفحة `/corrections`.
- **حادثة 2: ارتفاع معدل الخطأ في مصدر RSS**:
  1. ادخل إلى `/admin` -> تبويب «المصادر والجدولة» -> اضغط إيقاف المصدر مؤقتًا.
